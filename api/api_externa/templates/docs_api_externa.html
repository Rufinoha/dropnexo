Como funciona

Vocês expõem endpoints REST HTTPS. O DropNexo faz pull de produtos e estoque. Pedidos saem por webhook (contrato completo abaixo; envio automático em expansão).

Pull DropNexo → API de vocês (produtos / estoque / depósitos).
Push DropNexo → webhook (order.created / status / canceled).
Homologação Checklist + aprovação DropNexo antes de produção.
Completo JSON com todos os campos do catálogo e do pedido.

Homologação → produção

Todo parceiro começa em homologação. Vocês não mudam sozinhos para produção.

  1. Implemente os endpoints (HTTPS + auth).
  2. No card API Externa, informe URL, token e teste.
  3. Sincronize produtos/estoque.
  4. Solicitar produção — checklist em warehouses, products e stock.
  5. DropNexo aprova ou reprova.

Campos de produto

Esperados: sku, nome, descricao, preco, unidade, ncm, origem_fiscal, dimensões/peso bruto, imagens.

Opcionais (envie se existir): sku_pai, nome_variacao, atributos, external_id, preco_promocional, preco_custo, valor_atacado, valor_dropshipping, quantidade, gtin, cest, condicao, marca, grupo, categoria, peso_liquido_kg, peso_gramas, dimensao_caixa_cm, volumes, moq, prazo_envio_dias, frete_gratis, reposicao_estoque, producao, publicado, garantia_tipo, garantia_tempo, video_youtube, cfop, icms_situacao, pis_situacao, cofins_situacao, warehouses[], updated_at.

Variação: sku_pai + atributos. SKU é a chave estável.

Regras & boas práticas

  • SKU é a chave estável — não pode mudar.
  • Variação: sku_pai + atributos.
  • Paginação com next_cursor; sync com updated_since.
  • Imagens em URL pública HTTPS.
  • Checklist: warehouses + products com SKU + stock.
  • Homologação → solicitar → aprovação DropNexo → produção.
  • Campos opcionais: envie null ou omita — não invente obrigatoriedade extra.
